🔏 Verify it yourself

This page is the complete, self-contained verification contract for RUNECLAW's Provable Calls. You need nothing from us but public URLs — no account, no API key, no trust. If any check on this page ever fails, the receipt is broken and you should say so loudly.

1 · What gets sealed, and when

The moment the engine publishes a trading call — and the moment any Arena paper trade fills — the decision facts are serialized to a canonical JSON string and hashed with SHA-256. That hash is the seal. Outcomes attach to the same record later and mathematically cannot move the seal. A call that was edited, backdated, or invented after the fact cannot produce a matching hash.

Canonical payload · v1 · engine signal
{"v":1,"signal_key":<string>,"symbol":<string>,"direction":<string>,
 "entry_price":<number>,"stop_loss":<number>,"take_profit":<number>,
 "confidence":<number>,"pattern":<string|null>,"regime":<string|null>,
 "created_at":<ISO-8601 UTC>}

Key order is the contract. The served seal_payload is the exact sealed string — hash it verbatim, never re-serialize it.

Canonical payload · v2 · arena paper trade
{"v":2,"kind":"arena_trade","trade_key":<string>,"handle":<string|null>,
 "symbol":<string>,"direction":<string>,"entry":<number>,"leverage":<number>,
 "tp":<number|null>,"sl":<number|null>,"opened_at":<ISO-8601 UTC>}

Sealed at open — before anyone knows how the trade ends. The payload carries prices, leverage and times only; virtual balances never appear on any public surface.

2 · Verify one call

  1. Fetch GET /api/call/<key> (keys look like sig:… or arena:…).
  2. Compute sha256(seal_payload) over the served string, UTF-8, exactly as-is.
  3. It must equal seal. Then compare the payload's fields to current — any difference means the live record was rewritten after sealing.
import hashlib, json, urllib.request
d = json.load(urllib.request.urlopen("https://pmvc58g2.mule.page/api/call/KEY"))
assert hashlib.sha256(d["seal_payload"].encode()).hexdigest() == d["seal"]
p = json.loads(d["seal_payload"])
for k, v in d["current"].items():
    assert p.get(k) == v or k in ("trade_key", "signal_key"), (k, p.get(k), v)
print("intact ✔")

Every /call/<key> page runs the same math in your browser with WebCrypto — this snippet just proves you don't need our page to do it.

3 · Verify a whole day

At the end of each UTC day, every seal minted that day folds into one Merkle root, published at /api/roots (human view: /roots). The construction:

  • Leaves = the day's seals (64-char hex), deduplicated, sorted ascending.
  • Parent = sha256(utf8(leftHex + rightHex)) — the two hex strings concatenated.
  • An unpaired last node is promoted unchanged. A single leaf is its own root.

Receipts from completed days carry anchor.proof — a list of {pos, hash} steps. Replay it:

h = d["seal"]
for step in d["anchor"]["proof"]:
    pair = step["hash"] + h if step["pos"] == "L" else h + step["hash"]
    h = hashlib.sha256(pair.encode()).hexdigest()
assert h == d["anchor"]["root"]
print("anchored in", d["anchor"]["day"], "✔")

4 · Become a mirror

Copy any day's root anywhere durable and public — a tweet, a git commit, a chain memo. From that moment the day is frozen for everyone: we cannot back-insert a call into it without changing the root you hold. One mirrored hash timestamps every call of the day. That's the whole design: don't trust the screenshot — verify the call.

Honest scope: a seal proves the decision facts existed unchanged since sealing; a root proves set membership for its day; a mirror makes the day independently timestamped. None of this proves future performance, and none of it is investment advice. Operator-published on-chain anchoring of the same roots is planned and will be stated on the verify pages when live — never before.
