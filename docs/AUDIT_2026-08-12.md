## 1. Executive Summary

**Overall health: B.** This is a top-decile engineering culture in an unusual body: a one-month visible history, largely AI-authored, single human operator — yet it has an empty known-failures baseline enforced as a hard gate, a six-job CI whose comments read like incident postmortems, a preflight that parses CI rather than restating it, fail-closed live-trading gates re-asserted at order time, disciplined key custody (AES-256-GCM envelope + Fernet at rest, redacting logger), and demonstrated follow-through on its own June roadmap (all five P0s verifiably fixed). What keeps it from an A is that the repo's own doctrine is unevenly enforced: six confirmed instances of the house-banned "absent-is-zero" rendering bug survive on flagship truth-telling surfaces (the nightly self-audit structurally always reports `win 0% · net $0.00`), the deployed Docker image installs a dependency file that no audit gate covers (it still ships the three aiohttp advisories a commit "fixed" five days ago), and the live engine's event loop is blocked by synchronous HTTP calls on the same loop that runs stop-loss monitoring. No Critical findings; 7 High, ~26 Medium, 24 Low.

**Top 3 risks:** (1) *The audited artifact is not the deployed artifact* — four conflicting Python manifests; `pip-audit` covers a 10-package subset; the app's npm tree (the largest HTTP surface, 228 routes) has no advisory gate at all. (2) *Event-loop stalls in the live engine* — blocking urllib pulls every 20–30s, an audit chain re-hashed in full on every trade close, and a `/sync` command that can freeze the whole bot ~47s — precisely when the website is down and positions need protecting. (3) *Confidently wrong numbers on honesty surfaces* — self-audit, live-dashboard realized PnL, evening digest, and the public `win_rate` all render absent data as measured zeros/losses; for a product whose pitch is verifiable honesty, this is a credibility risk beyond its bug severity.

**Top 3 opportunities:** (1) The ratchet machinery already exists — extending mypy to the three files where the attribute bugs live, and unifying manifests, closes whole bug classes for hours of work. (2) The pure-renderer extraction pattern is proven in-repo (7 extracted JS view-models) — applying it to the three named Telegram card builders converts untestable inline money-claims into planted-state tests. (3) Consolidating four bot→web bridges and three dashboard generations into one deletes an entire class of rendering-drift sites the repo has the most scar tissue from.

## 3. Audit Report

### 3.1 High-severity findings (all verified CONFIRMED)

**H1. The deployed image installs the pre-advisory dependency pin; the security fix landed only in the manifests CI audits.** [fact]
`bot/requirements.txt:8` pins `aiohttp==3.14.1`; commit `7f2e715` ("aiohttp 3.14.1 → 3.14.3, PYSEC-2026-3545/3546/3547") bumped only `requirements-ci.txt:12` and `requirements.lock:11`. `Dockerfile:16-17` installs `bot/requirements.txt` into the production image; CI's SCA gate runs `pip-audit -r requirements.lock` (`ci.yml:77`). The container that trades real money ships the three advisories the repo believes it fixed, while the audit gate reports green. `pyproject.toml:19` carries a third pin (3.13.4). This is the repo's own named defect — a check whose coverage is narrower than the confidence placed in it.

**H2. Engine run loop makes blocking urllib calls (15s timeout) on the event loop every 20–30s.** [fact]
`bot/core/engine.py:3547-3566`: async `_maybe_flatten_web_requests` calls `fetch_flatten_pending()` — a synchronous `urlopen(req, timeout=15)` — every 20s whenever `BOT_SYNC_SECRET` is set (i.e., normal production); `_maybe_pull_web_credentials` (engine.py:2515, 30s throttle) chains up to six such calls. This is the same loop running SL/TP monitoring, the WS feed, and all Telegram handlers (`bot/main.py:404-515`). A slow/unreachable website blocks position protection for up to 15s per call — and sync code never yields, so the tick's `asyncio.wait_for` cap can't interrupt it.

**H3. AuditChain re-reads and re-hashes its entire never-rotated JSONL up to six times per live trade close, synchronously on the loop.** [fact]
`bot/utils/audit_chain.py:268-285`: every `append()` reads the whole file to find the tail; every 50th append re-parses it all (`:137-164`); the close path fires multiple appends (`bot/core/live_executor.py:8253-8257`). Cost is O(chain length) per close and the chain grows forever (no rotation anywhere; `backup.py` only copies it). A long-running live bot degrades steadily on its hottest, most safety-relevant path.

**H4. The nightly self-audit structurally always reports `win 0% · net $0.00`.** [fact]
`bot/core/self_audit.py:244` reads `getattr(t, "net_pnl", 0)` from `live_executor._closed_trades`, a `list[LivePosition]` — which stores PnL as `pnl_usd` and has no `net_pnl` (dataclass at `live_executor.py:415-462`). Every row defaults to 0; `win_rate` computes to 0.0 (not None). The surface whose entire purpose is honest self-reporting renders a confident, wrong claim for any real window. This is the *literal* `getattr(t, 'net_pnl', 0)` shape CLAUDE.md's 2026-07-31 retro names as the one its greps missed.

**H5. Live-mode dashboard realized PnL reads a file path and key schema the executor never writes.** [fact]
`bot/skills/scan_skill.py:44-67` reads `closed_trades.json` from `bot/` or repo root; the only writer persists to `$RUNECLAW_STATE_DIR/closed_trades.json` (`live_executor.py:316-317`). Even on a path hit, it reads keys `net_pnl`/`pnl` while the writer emits `pnl_usd` (`live_executor.py:8442-8467`). Net effect: a live account's realized results render as 0% win rate with realized PnL missing, on the payload feeding the website's agent panel (`scan_skill.py:515-518`).

**H6. docker-compose runs three RuneClawEngine instances over one shared `data/`; the bridge's `/confirm` is a second, gate-light execution path with last-writer-wins paper state.** [fact]
`docker-compose.yml` runs the bot plus `uvicorn api_bridge:app --workers 2`; each bridge worker constructs its own engine (`api_bridge.py:331`), all mounting the same `./data` volume. `api_bridge.py:717` opens positions via `engine.portfolio.open_position` directly — bypassing `engine.confirm_trade`, which `bot/web/user_gateway.py:11` calls "THE single execution path." `PortfolioTracker` auto-saves on every open/close, so three processes clobber the paper book (the record feeding dashboards and public track surfaces). Not Critical only because the live path stays single-process.

**H7. Four bot→web bridges and three dashboard generations coexist; one generation is pushed to by the engine but deployed by nothing.** [fact/judgment]
Channels: `app/lib/gateway.js` (pull, `WEB_GATEWAY_SECRET`, :8080), `api_bridge.py` via `app/routes/insight.js` (`BOT_API_URL`, :8000), `bot/utils/website_sync.py` (push into MySQL, `BOT_SYNC_SECRET`), `bot/core/dashboard_pusher.py` → `dashboard_api.py` (:9090, `DASHBOARD_API_KEY`) — the last referenced by no deploy path yet still constructed and started by the engine (`engine.py:423,2428`). Three frontends serialize portfolio state independently. Every extra rendering of the same value is a fresh site for the honesty-bug class this repo documents recurring twenty-plus times in one day.

## 4. Improvement Strategy

**Theme A — Audit what you ship (deps & artifacts).** *Target:* one authoritative Python dependency source; the file Docker installs is the file CI installs, tests, and pip-audits (with transitives); app/ gets the same npm advisory ratchet token/ has; GitLab mirror either works or is deleted. *Principle:* the repo's own — "running a subset and reporting it as the whole is the defect this repo spends most of its guard tests preventing." *Trade-off:* keep the deliberate cryptography-pin deferral and the 8 RustSec baseline advisories (documented, reasoned); don't chase a full lockfile toolchain (pip-tools) if a generated true freeze is enough. *Done signals:* `pip-audit` target == Dockerfile install source; a CI assertion that `bot/requirements.txt`, `requirements-ci.txt`, and the lock agree on shared pins; `audit_gate.mjs`-style ratchet running in the web-app job; `.gitlab-ci.yml` green or gone.

**Theme B — Protect the live event loop.** *Target:* nothing on the engine loop blocks on network or O(n) file I/O; the audit chain appends in O(1). *Principle:* the loop that guards positions must never wait on the website, because website-down and positions-at-risk correlate. *Trade-off:* don't rewrite sync plumbing as native asyncio wholesale — `asyncio.to_thread` at the four call sites is enough; keep the hash chain's tamper-evidence, just cache tail state and rotate with chained checkpoints. *Done signals:* a test asserting no `urlopen` executes on the running loop (seam: inject a probe transport); audit-chain append cost independent of file size; `/sync` under a slow website no longer delays an unrelated command.

**Theme C — Finish the honesty campaign on its own terms.** *Target:* zero instances of the CLAUDE.md banned-shapes table on reachable surfaces; the two consolidation modules (`win_rate.py`, `trade_stats.js`) are the *only* win-rate/PnL computers; one cross-language golden fixture pins them to each other. *Principle:* "write the assertion, then re-run the search" — the repo's own practice, applied to the six confirmed sites. *Trade-off:* leave the ~360 documented best-effort exception swallows alone (deliberate engineering, one drifted copy fixed under M5); don't refactor guarded look-alike sites (the repo's reachability discipline is correct). *Done signals:* planted-state test makes self-audit report a non-zero window (red today); mypy gate includes `self_audit.py`, `scan_skill.py`, `proactive_monitor.py`; a source test (comment-stripped) over the banned shapes passes repo-wide.

**Theme D — One rendering path per fact; seams where money claims are made.** *Target:* one bot→web topology diagram with each channel justified or deleted (the `dashboard_api.py` generation retired or deployed — decide); `api_bridge` cannot open positions except through `engine.confirm_trade`; the three Telegram card builders become pure renderers with planted-state tests; dashboard.js continues model-extraction (no rewrite). *Principle:* every duplicate rendering is a future divergence; every inline card is untestable. *Trade-off:* do NOT decompose telegram_handler or dashboard.js wholesale — extract only money-claim renderers (the repo's own "do not convert wholesale" rule); MemoryDB stays (it's load-bearing for fast tests) but gets a real-MySQL CI job as the fidelity backstop. *Done signals:* zero engines constructed outside bot/main + a topology doc; `/confirm` routes through the gated path; three new `*_model`-style renderer tests; a green app-suite run against real MySQL in CI.

**Theme E — Make the meta-layer tell the truth.** *Target:* Makefile/CONTRIBUTING teach `preflight.py` and the gate; README/agent_card/badges/watchdog match reality; the production-status contradiction resolved deliberately. *Principle:* on a repo whose product is verifiable claims, stale docs are product defects. *Trade-off:* don't build badge automation; delete hand-maintained counts instead. *Done signals:* `make test` runs the gate; clone URL == origin; agent_card regenerated or generated-from-code; a single sentence in README states the real-funds stance.
