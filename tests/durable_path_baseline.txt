# Relative "data/…" and "logs/…" literals that are CORRECT as written.
#
# `test_no_module_resolves_durable_state_against_the_cwd` flags every such
# literal, because a relative path means whoever launched the process decides
# which file it reads, and a missing file is CREATED rather than reported.
# The rule cannot see where a value FLOWS, so a default that its constructor
# anchors looks identical to one nothing anchors. This file is where that
# difference is written down.
#
# A RATCHET IN BOTH DIRECTIONS, same as tests/unreachable_baseline.txt:
#   - a new entry means somebody added an unanchored durable path, and the
#     reason has to be argued in the same commit
#   - an entry that no longer matches must be DELETED in the same commit, so a
#     stale exemption cannot hide a real one
#
# Format: <path> :: <literal> :: <reason>

# ── the default is anchored by the constructor that receives it ────────────
# Each of these is a parameter default; `__init__` passes it through
# state_path(), so the relative form never reaches the filesystem. Anchoring
# at the owner rather than at every call site is what lets the call sites
# below stay relative too.
bot/utils/user_store.py :: "data/users.json" :: UserStore.__init__ wraps it in state_path()
bot/utils/audit_chain.py :: "logs/audit_chain.jsonl" :: AuditChain.__init__ wraps it in state_path()
bot/core/trade_journal.py :: "data/trade_journal.json" :: TradeJournal.__init__ wraps it in state_path()
bot/core/slippage.py :: "data/slippage_state.json" :: SlippageTracker.__init__ wraps it in state_path()
bot/core/smart_exits.py :: "data/limit_distance_state.json" :: __init__ wraps it in state_path()
bot/proofofpnl/leaderboard.py :: "data/proofofpnl_leaderboard.json" :: __init__ wraps it in state_path()
bot/proofofpnl/publish.py :: "data/proofofpnl_publication.json" :: __init__ wraps it in state_path()
bot/proofofpnl/seasons.py :: "data/proofofpnl_seasons.json" :: __init__ wraps it in state_path()
bot/core/order_flow.py :: "data/learning/order_flow_snapshots.jsonl" :: warm_oi_history anchors `path` on its first line

# ── the call site hands a relative value to an anchored owner ──────────────
bot/core/engine.py :: "logs/audit_chain.jsonl" :: passed to AuditChain, which anchors it
bot/core/engine.py :: "data/risk_state_{safe}.json" :: passed to RiskEngine(state_file=), which anchors it
bot/core/engine.py :: "data/proofofpnl_user_scratch.json" :: passed to PublicationStore, which anchors it
bot/risk/multi_portfolio.py :: "data/portfolio_{user_id}.json" :: passed to PortfolioTracker(state_file=), which anchors it
bot/core/venue_key.py :: "data/venue" :: _VENUE_SUBDIR; both readers go through state_path() — venue_state_path() joins it inside state_path(), and venue_root() IS state_path(). The relative form never reaches the filesystem. Added because the FIRST version of this module did leak it: _load_existing_venues globbed the bare literal, so the restore scanned whatever directory the process was launched from, found nothing, and every split venue silently reset to the default paper balance. This test caught that.
bot/risk/person_peak.py :: "data/person_equity_peak.json" :: _STATE_FILE; the ONLY use is `state_path(path or _STATE_FILE)` in __init__, and every read/write goes through the anchored self._path. A relative default here would be worse than most: the peak is a high-water mark, so a store that silently found no file would report NO DRAWDOWN on an account that is deeply down.
bot/core/venue_selection.py :: "data/venue_selection.json" :: _STATE_FILE; the only use is `state_path(path or _STATE_FILE)` in __init__ and every read/write goes through the anchored self._path. A relative default would make the store find no file when launched from elsewhere, and an empty selection means SINGLE VENUE — so it would fail safe, but silently, and a user who had chosen two venues would be quietly dropped back to one with nothing said.
bot/config.py :: "data/portfolio_state.json" :: CONFIG default read by PortfolioTracker, which anchors it
bot/config.py :: "data/proactive_watch.json" :: CONFIG default read by ProactiveMonitor._watch_state_path, which anchors it
