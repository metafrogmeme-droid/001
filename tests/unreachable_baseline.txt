# ── UNBUILT FEATURES, not rot — a product call, not a cleanup ───────────────
# Audited one by one before deleting anything, and only ONE was actually dead:
# bot/_compat.py, a shim re-exporting bot.compat "so any stale imports keep
# working", which nothing had imported for a long time. Deleted; zero
# information lost.
#
# The entries below are a different thing and deleting them would destroy work
# rather than remove rot. Each is finished, coherent code for a feature nobody
# wired, so the question is "do we want this signal?" and that is not a
# question a cleanup gets to answer.
#
# basis.py and market_cap.py LEFT this list — the last two names on the
# roadmap's "real-time signal fusion" line — and they went the way seasonality
# did: fixed first, then wired as CONTEXT that votes on nothing.
#
# Both carried the defect that comes with never being read. market_cap.py built
# every number with `.get(k, 0)`, so an unreadable FDV produced
# `fdv_mcap_ratio = 0.0` on a field documented ">2.0 = high inflation risk" —
# the SAFEST reading it can carry, and CoinGecko returns a null FDV for every
# token with no max supply, so that was the normal response for a whole class
# of asset rendered as an all-clear. An unknown total supply produced
# `supply_ratio = 0`, which claims none of the supply circulates. basis.py read
# `ticker.get("last", 0)`, and a ticker whose `last` is NULL answers None, so
# `None <= 0` raised and a successful fetch of an unpriced ticker was logged as
# a network failure; its `get_cached()` ignored the TTL that `get_basis()`
# enforced; and `basis_pct * 365` fabricated an "annualized" yield from an
# instantaneous premium.
#
# Wiring also needed a guard neither had: the engine's exchange factory is a
# COROUTINE function, and basis.py called it synchronously. bot/core/
# exchange_flow.py already carries that guard, with a docstring recording the
# same bug shipping once — "the provider never returned live funding/OI data at
# all". Wired without it, this module would have been dead in a way no
# reachability checker can see, because it would have had a caller.
#
# seasonality.py LEFT this list, and what it was hiding is the argument for
# reading this file rather than trusting it. It was not merely unwired: nothing
# imported it AT ALL, not even a test, and it carried a defect of exactly the
# shape CLAUDE.md tabulates. Every empty hour/weekday bucket was seeded with
# 0.0, so with the minimum accepted input — 48 hourly candles, two calendar
# days — it named WEDNESDAY the best day to trade, from data that had never
# seen a Wednesday, and scored the verdict NEUTRAL off the same invented zeros.
# A fabricated 0.0 beats a real negative return. Fixed (absent buckets are
# None, best/worst range over observed buckets only, a thin bucket is UNKNOWN
# rather than neutral) and wired into the analyzer as CONTEXT — never a vote.
#
# The two RWA research scripts LEFT this list, and the note that put them here
# was wrong in a way worth keeping. It said they have no `__main__` guard "so
# they cannot be run at all". They ran perfectly well — every statement was
# top-level, so executing the file executed the study. What the missing guard
# actually meant was the reverse and worse: IMPORTING either module ran the
# whole study, every curl to Bitget and every print, fired by anything walking
# the tree importing what it found — including the reachability checker that
# catalogued them here. The defect was never "cannot run"; it was "runs when
# nobody asked". Both have a main() and a guard now, which is what makes them
# entry points to the checker and what stops the study being a side effect of
# reading the file. Pinned by tests/test_research_scripts_are_importable.py.
