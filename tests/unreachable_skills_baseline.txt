# Reachability is decided by bot/skills/skill_permissions.py (both chat

# dispatch-by-name from bot/ or a repo-root module (how MCP reaches
# explain_trade). A skill in neither is in here.

# tests/test_registered_skills_are_reachable.py enforces this file as a
# RATCHET IN BOTH DIRECTIONS: a new dark skill fails, and an entry that becomes
# reachable must be deleted in the same commit. Same rule as
# known_failures.txt, for the same reason.
#
# Six entries today, every one triaged: each line below is a decision with
# its reason, not a backlog.

# ── TRIAGED: bot/skills/macro_skills.py ────────────────────────────────────
# Five skills that each advertised a slash command — /macro, /eventrisk,
# /compliance, /approve, /kill — dispatched by NOTHING when this was found:
# no @guard command handler existed for any of them, they were absent from
# SKILL_PERMISSION (so Telegram free text refused and web chat's derived set
# excluded them), and bot/mcp/server.py uses an explicit tool allow-list that
# omits all five.
#
# Being unrunnable is why nobody noticed that all seven of the module's
# attribute probes named fields that do not exist on the real objects. Those
# are fixed (tests/test_macro_skills_read_real_state.py). Three are reachable
# now — /eventrisk and /compliance as commands, macro_brief as `/macro brief`
# plus a chat tool and free-text skill under `macro` (it advertised `/macro`,
# which the calendar already answers to, so it became a sub-mode of that
# command rather than a second name for one subject). WIRING THE LAST TWO IS
# A PRODUCT DECISION, NOT A BUG FIX, and each argues against it on its own
# merits:
#
#   kill_switch  — /halt already works and is the complete stop (it cancels
#                  pending ideas, halts per-user risk engines and transitions
#                  the engine to HALTED). A SECOND emergency-halt command
#                  beside it is a hazard in an emergency, not a feature.
#   request_live_approval
#                — needs an `engine.approval_manager` that does not exist.
#                  ComplianceEngine.issue_approval_token() is close but takes
#                  a subject_id this skill has no way to supply.
kill_switch
request_live_approval

# ── TRIAGED: the rest of the registry ──────────────────────────────────────
# Each of these was read before being left here, and the reason is the entry.
#
#   execute_paper_trade
#                — `engine.confirm_trade(trade_id)` with NO user id. The two
#                  real confirm surfaces (the inline button and the web
#                  confirm) both pass `user_id=caller_uid`, which is what
#                  scopes a confirmation to the account that owns the idea;
#                  reached from chat this would confirm any pending idea as
#                  the operator. It is the confirm button without its
#                  ownership check. If it is ever wanted from chat it goes
#                  through DANGEROUS_SKILLS to the guarded path, like `halt`.
#   feedback     — writes to the shared learning store keyed by a decision
#                  audit id, and no user-facing card prints one, so a
#                  permission would offer a form nobody can fill in. Wire it
#                  when a card carries the id.
#   getclaw      — an SDK bridge probe that answers "adapter ready" and a
#                  boolean. Not a user feature; kept registered so the
#                  registry describes what the adapter package installs.
#
# quant_analyze LEFT this list, and the note that kept it here named the wrong
# blocker. It said the obstacle was a TIER decision — "a permission alone would
# give away more than deepscan for free" — which was true and was the smaller
# half. Driven against a 503 the skill returned a full report: `Hurst 0.851 →
# trending memory`, `ADX 22.9`, a GARCH forecast, `Composite Score 0.381` and
# `QUANT GATE: REJECTED`, every number modelled from
# `_generate_synthetic_ohlcv(150, seed=hash(symbol))` and nothing on the card
# saying so. The word "synthetic" reached the audit log only. Being unwired is
# why that survived — it is the `market_cap`/`basis`/`seasonality` shape again,
# a module defective in exactly the way a module nobody reads becomes
# defective, and the fixing was most of the work.
#
# The tier question then answered itself on the ladder's own stated basis (cost
# to serve): seconds of in-process modelling is what `pro` means, so
# `quant_analyze` sits at `pro` beside deepscan, patterns and analyze_asset,
# and `/quant` is @guard("analyze") — the same read-only question about one
# symbol, one layer deeper, so it reuses a permission trader and paper hold.
